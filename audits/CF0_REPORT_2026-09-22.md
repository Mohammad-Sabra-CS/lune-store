## Safety and tooling details

- `cf:build` requires a checkout without local env files, strips database,
  admin, mail and Cloudflare credentials from the child environment and invokes
  `next build` directly. It never invokes the deployment migration script.
  This is a **CF-0 fixture build**, not the future production build pipeline.
- Wrangler has `send_metrics: false`, `workers_dev: false`, `preview_urls: false`,
  no account ID and no routes. R2 and Durable Object declarations were exercised
  locally only. There is no D1/Hyperdrive binding.
- Cache configuration uses R2 plus a DO queue and a single tag-cache shard.
  Automatic remote zone purge is not enabled; it requires separate zone/token
  configuration and verification if introduced later.
- `cf:check` uses `wrangler deploy --dry-run`. The installed Wrangler source was
  checked: dry run skips account authentication, asset upload and binding
  provisioning. Both runs end with `--dry-run: exiting now.` Telemetry is disabled.
  The earlier approval rejection on the separate storefront attempt does not
  describe these completed local runs.
- `cf:smoke` uses the supported `populateCache local` command, then
  `wrangler dev --local` on loopback. It captures stderr directly and never logs
  in, submits an order or edits a product. Local Cloudflare metadata fetching is
  disabled. An explicit inspector port avoids this container's unsupported
  network-interface enumeration; no security or runtime guard was disabled.
- OpenNext's platform-proxy bootstrap prints warnings about internal DO exports.
  The actual Worker starts with local bindings, but queue/tag mutation behavior
  remains part of G2 rather than being inferred from startup.
